# 内容编写指南（V1）

> 面向写课的人：如何用 YAML 写一节微课、保证一次通过
> `python tools/validate.py`。技术规格以开发规格 §6（教材格式与内容协议）
> 与内容蓝图为准；本文只讲"怎么写才合规"。

## 1. 写课前的自检流程

```bash
cd /home/hatch/workspace/python-relearn
.venv/bin/python tools/validate.py        # 内容校验：失败即停，看清报错里的文件/步骤/题目 ID
.venv/bin/python -m unittest discover -s tests   # 全量测试（含样例蓝图与 fixtures 运行）
```

规则：**先写内容文件，再跑校验，最后才看构建产物**。`tools/validate.py`
的报错都会带文件路径、步骤 ID 或题目 ID，不会静默跳过；按报错逐条修，
修完再跑一次。新增课程只应需要"加内容文件 + 更新目录 + 相应内容测试"，
不需要改阅读器逻辑。

## 2. YAML 字段表

### 2.1 course.yaml（目录）

| 字段 | 规则 |
|---|---|
| `schemaVersion` | 固定 `1` |
| `courseId` | 非空字符串，全站课程标识 |
| `title` | 非空字符串 |
| `pythonVersion` | 非空字符串，如 `"3.13"`（注意引号，避免 YAML 把 `3.13` 当数字） |
| `modules[]` | 非空列表；每项 `id`（模块 ID）、`title`、有序 `lessonIds[]` |

目录中的模块归属和顺序是**唯一依据**：课程顺序、编号、复习题排序都从这里来。

### 2.2 单课（content/lessons/<id>.yaml）

| 字段 | 规则 |
|---|---|
| `schemaVersion` | 固定 `1` |
| `id` | 与文件名一致；小写字母/数字/短横线；全站唯一 |
| `title` | 非空 |
| `goal` | 非空，一句话能力目标 |
| `revision` | 整数，内容修订时递增（见 §5） |
| `status` | 只允许 `draft` / `published`；未完成的课必须标 `draft`，且 `draft` 不进入发布与进度统计 |
| `prerequisites[]` | 字符串列表；每项必须存在于目录顺序中且**排在当前课前面** |
| `steps[]` | 非空列表，见下 |

### 2.3 四种步骤（通用字段：`id` 课内唯一、`type`、`title`）

**`read`**——说明、误区或总结：

| 字段 | 规则 |
|---|---|
| `bodyMd` | 非空，多行 Markdown 正文 |

**`reveal`**——先显示示例/问题，点击展开结果/解释（"先预测，再展开"）：

| 字段 | 规则 |
|---|---|
| `bodyMd` | 非空，先显示的示例或问题 |
| `revealLabel` | 非空，按钮文字（如"先预测，再点开展开实际输出"） |
| `revealMd` | 非空，展开后的结果或解释 |

**`quiz`**——单选题（判断题 = 两选项单选）：

| 字段 | 规则 |
|---|---|
| `questionId` | 全站唯一；建议 `<lessonId>-q1` 格式，**不用数组下标做永久身份** |
| `revision` | 整数；题意/答案变化时递增（见 §5） |
| `promptMd` | 非空，题干 |
| `options[]` | **2—4 个**选项，每项 `id`（题内唯一）、`textMd`（非空）、`explanationMd`（非空） |
| `correctOptionId` | 必须存在于 `options` 中；**恰有一个正确项** |
| `explanationMd` | 非空，总解析 |

**`practice`**——模块实践（只出现在模块末尾的课）：

| 字段 | 规则 |
|---|---|
| `taskMd` / `hintMd` / `solutionMd` | 均非空：任务 / 分级提示 / 参考解法 |
| `acceptance[]` | 非空列表，每项非空：验收清单 |

一课**最多一个** practice，只有一个整体完成状态，不逐条保存清单。

## 3. ID 规则

- 仅允许小写英文字母、数字、短横线（正则 `^[a-z0-9-]+$`）。
- 课程 ID 全站唯一；题目 ID 全站唯一；选项 ID 题内唯一；步骤 ID 课内唯一。
- 题目建议 `<lessonId>-q1` / `-q2`；**改标题、改文字、调课程顺序都不改 ID**；
  目录调整不重置学习进度。

## 4. 步骤类型选用

默认七步（蓝图 §3）：①旧知识唤回与目标（read）→ ②核心机制（read）→
③先预测再展开的主例（reveal）→ ④关键对照或误区（reveal）→
⑤小测一（quiz，诊断阅读与解释）→ ⑥小测二（quiz，诊断修改/迁移）→
⑦回忆与独立任务（read）。模块最后一课在末尾加 practice。

较长内容拆成更多短步骤，**不要把整节塞进一个内容块**；每步只围绕一个问题。
"独立任务"是总结里的短迁移建议，不新增模块实践、不加完成状态。

## 5. quiz 写作要求（内容蓝图 §9）

1. **2—4 个选项，恰一个正确**。每个错误选项对应**一个明确误解**，
   必须在该选项的 `explanationMd` 里写清具体错因；不用"以上都对"、
   未讲过的语法或纯措辞陷阱。
2. **解析禁空话**：`explanationMd`（总解析与每选项解析）都不许为空，
   校验器会拦截空解析。正确选项讲清"为什么对"，错选项讲清"错在哪、
   错的理解会导致什么"。
3. 第一题主要诊断阅读与解释，第二题主要诊断修改、选择正确实现或迁移；
   出题锚点以内容蓝图每课的"小测"表格为准（蓝图已锁定场景与判定标准）。
4. 小测检查代码理解，不考冷僻语法记忆。

## 6. revision 规则（开发规格 §6.3）

- **普通内容修订**（改文字、改标题、调顺序）：递增该课 `revision`；
  已读记录保留，不重置。
- **题目含义、正确答案或选项内容发生影响作答的改变**：必须递增该题
  `revision`。旧版本作答记录不得恢复成新题答案；复习页会标记
  "题目已更新，需重新作答"；首次提交新版本时替换旧记录，次数重新统计。
- 删除的课程/题目不参与当前统计，但不自动擦除其本地记录。

## 7. 篇幅目标（开发规格 §5.3）

- 每步正文目标 **100—250 个汉字**，避免超过 350 字。
- 代码一般 **4—10 行**，超过 12 行必须拆分或说明必要性；
  尽量控制在 **40 个等宽显示列**内（中文按两列估算）。
- 例子优先用文件名、日志、记录、计数、小型数据清洗；
  不用数学推导掩盖编程基础；每课至少明确一个易误解机制、
  一项实际用途或面试关联。
- 讲解用中文，保留必要英文术语；以 Python 3.13 为统一示例基线。

## 8. 禁止项与 fixtures

- **正文禁止原始 HTML、自定义脚本、嵌套组件**：只写普通 Markdown 与
  代码块；构建时 Markdown 渲染禁用原始 HTML，模板启用自动转义。
- **所有声称可运行的示例必须验证实际输出**：示例代码放进
  `content/fixtures/<lessonId>/`，文件名与内容对应，
  每个 `.py` 配一个同名 `.expected.txt`（逐字节期望输出）；
  `tests/test_examples.py` 会用 `sys.executable` 真实运行并比对。
  故意报错的例子必须标明异常类别与原因；不要用未解释的随机性、
  集合显示顺序或依赖外部服务的响应做固定答案。
- 不要把题干、答案、课程顺序复制进 JavaScript：课程只在内容文件维护。
